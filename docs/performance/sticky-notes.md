# 多便签性能测试与优化

测试日期：2026-10-26（Asia/Shanghai）。本次使用独立数据和隐藏的原生 WebView2 窗口，没有操作正式应用窗口或读取正式便签。

## 测试口径

- 前端使用 Vite 生产构建，原生测试程序使用 Rust debug 构建；优化前后采用相同构建方式。
- 分别打开 1、5、10、20 个便签窗口，窗口尺寸为 360 × 440。
- 每张便签包含约 2 KiB 中文富文本，一半包含 256 × 256 的 BMP，内联 base64 约 256 KiB。
- 另准备 3,000 条独立测试待办及对应备份，用于检验便签是否重复加载主应用数据。
- 全部编辑器就绪后空闲 6 秒，随后每张便签同时执行 8 次内容修改，间隔 600 毫秒；等待保存和回收，再关闭一半窗口并观察 6 秒。
- CPU 包含测试程序及其 WebView2 子进程，按本机 16 个逻辑处理器折算整机百分比。内存是这些进程的**私有提交总量（MiB）**，不等同于任务管理器默认“内存”列，也不是去重后的物理工作集。
- 每个场景是短时采样，CPU 平均值有波动。隐藏窗口不包含真实前台键盘输入和完整的屏幕重绘成本；不能据此保证数小时运行、任意窗口数量或大型图片的资源上限。

## 最终复测结果

内存取编辑和保存结束后的稳定阶段平均值，CPU 取所有便签同时编辑阶段的平均值。

| 打开便签数 | 优化前私有提交 | 优化后私有提交 | 优化前编辑 CPU | 优化后编辑 CPU |
| --- | ---: | ---: | ---: | ---: |
| 1 | 245.45 MiB | 228.89 MiB | 0.10% | 0.03% |
| 5 | 653.27 MiB | 567.34 MiB | 0.34% | 0.15% |
| 10 | 1,145.84 MiB | 969.02 MiB | 0.57% | 0.30% |
| 20 | 触及 2 GiB 测试上限，主动终止 | 1,822.64 MiB | 未完成 | 0.74% |

10 张场景的稳定私有提交降低约 15.4%，编辑 CPU 降低约 47.4%。窗口全部就绪的时间从 5,241 毫秒降至 3,420 毫秒（约 34.7%）。早一轮相同方案的编辑 CPU 为 0.23%，因此应把 CPU 改善看作约一半，而非固定比例。

20 张场景关闭其中 10 张后，最后一次采样的私有提交降到 1,116.22 MiB，较关闭前约减少 706 MiB。稳定空闲阶段的 CPU 接近 0。独立 WebView2 窗口仍有明显的基础成本，不能无限制地同时打开大量带图便签。

最终 20 张便签均完整保存了全部 8 次修改；纯文本搜索摘要不包含图片 base64。验证结果和可执行文件哈希保存在 [sticky-notes-verification.json](sticky-notes-verification.json)。完整采样见 [优化前](sticky-notes-before.json)、[优化后](sticky-notes-after.json)。

## 已实施的改动

1. 按窗口类型动态加载页面；便签不再加载主应用、剪贴板及待办窗口的组件，也不再初始化主应用的任务和备份数据。
2. 每张便签通过 `get_sticky_note` 只获取自身内容；“所有便签”只获取纯文本摘要和状态，不传输所有图片及 HTML。
3. 将整份 JSON 的反复读取和重写改为原生共享缓存、每张便签一个文件的原子保存；不同便签互不覆盖，未变更的内容跳过写盘。
4. 合并输入后的富文本清理与自动保存，避免每次键入都重复解析并复制图片数据；保留粘贴、拖入和载入时的内容清理。
5. 合并列表刷新事件；列表搜索复用已生成的摘要。选择格式未变化时，不重复更新工具栏状态。
6. 关闭窗口继续使用 `destroy`，释放对应 WebView；内容保留，可从列表重新打开。

## 数据迁移

首次运行会把旧的 `sticky-notes.json` 自动迁移到数据目录内的 `sticky-notes/*.json`。只有每张便签均成功保存后才写入格式标记，原始 JSON 保留为迁移备份；迁移后的删除不会从旧文件中复活便签。迁移应用数据目录时，会同时复制新的便签目录。

不要只复制旧的 `sticky-notes.json` 作为迁移后的最新便签备份；应保存整个数据目录。

## 复现当前版本

先使用满足项目要求的 Node 版本运行 `npm run build`，然后在仓库根目录的 PowerShell 中执行：

```powershell
$env:TAURI_CONFIG = '{"identifier":"com.alxian.dotime.sticky-stress","build":{"devUrl":null,"frontendDist":"../dist"},"app":{"windows":[]}}'
cargo build --manifest-path src-tauri/Cargo.toml --example sticky_notes_stress --offline
Remove-Item Env:TAURI_CONFIG
./scripts/benchmark-sticky-notes.ps1 `
  -Executable ./src-tauri/target/debug/examples/sticky_notes_stress.exe `
  -OutputDirectory X:/path/to/a/new/test-directory `
  -Counts 1,5,10,20
```

测量脚本需要 Windows SDK 的 `mt.exe`，用于给 Rust example 嵌入 Common Controls v6 清单；进程统计权限不足时需要在允许查询测试进程的终端中运行。输出目录必须为新的测试目录，测试程序使用独立应用标识，不启动正式应用或托盘。私有提交超过 2 GiB 会主动停止该场景。

本轮检查：175 项前端测试通过，36 项 Rust 测试通过，1 项需联网下载的测试按原配置忽略；TypeScript 检查及前端生产构建通过。

原生库和独立测试程序均已编译运行。最后重建普通 `dotime.exe` 时，现有运行实例占用了输出文件，链接输出未能更新；需要先完整退出当前 doTime，再重新运行开发版完成重编译。测试没有强制结束正式应用。
